# 바이브코딩 2기 현황판

바이브코딩 2기 알림신청(메타 광고) 캠페인 일일 현황 대시보드. **목표 알림신청 30,000명 / 광고예산 1.5억 / 블렌디드 목표 CPA 5,000원.**
매일 아침 `/admin` 에서 알림신청 일별값만 입력하면, 서버가 메타 API 에서 전일 광고 데이터를 자동 수집 → `data/vibe2.json` 갱신 → GitHub 커밋 → Vercel 자동 재배포 → 대시보드 최신화.

노마5기 현황판(`~/Desktop/noma5-dashboard`)에서 코드를 복사해 2기용으로 개조한 별도 프로젝트다. **noma5-dashboard 는 건드리지 않는다.**

## 1기 비교

`data/vibe1.json` 은 **바이브코딩 1기 확정 실적 스냅샷**(고정, 갱신하지 않음)이다.
출처: 오픈알림신청_정리_20260720(구글 드라이브) + Meta Ads API 캠페인 일별 조회(2026-07-20 11:11).

1기 최종: 알림신청 **7,960명** / 광고비 **₩47,998,593** / CPA **₩6,030** / 판매 **491건** / 매출 **4.47억** (구매전환 6.17%).

대시보드의 `1기 비교` 섹션은 두 기수를 **1차 LIVE = D-DAY 로 정렬**해서 겹쳐 본다 (달력 날짜로는 시작일이 달라 비교가 안 된다).

- 1기 1차 LIVE 7/7, 2기 1차 LIVE 9/8 → 같은 D-day 끼리 비교
- 2기는 D-21 부터, 1기는 D-15 부터 집행 → 앞 6일은 1기 누적 0 (미집행 구간으로 표시)
- `1기 페이스 ×3.77` 선 = 1기 곡선을 3만 명으로 환산한 기준선. 실측이 이 선 위면 3만 페이스.

`lib/benchmark.ts` 가 D-day 정렬·배수·페이스를 전부 계산한다. JSON 에는 원본만 있다.

## 데이터 원칙

- 메타 지표(지출·노출·클릭·CTR·CPM·빈도·openEvent)는 **API 자동**, 어드민 알림신청 일별값은 **수동 1개**.
- `data/vibe2.json` 에는 **원본값만** 저장. CPA·달성률·예상착지·기대수익 등 파생값은 전부 화면(`lib/metrics.ts`)에서 계산.
- `openEvent` 는 custom_conversions(name=openEvent) ID 해석이 1순위. **`offsite_conversion.fb_pixel_custom` 로는 절대 폴백하지 않는다** — 그건 모든 커스텀 전환의 합계라 과대집계된다.
- 메타 캠페인 ID 는 2기 캠페인 개설 후 `META_CAMPAIGN_IDS` 에 넣는다. **2기 알림신청 캠페인만** 넣을 것.

## 환경변수

`.env.example` 참고. Vercel 환경변수(또는 로컬 `.env.local`)에만 실제 값을 넣는다.

| 키 | 예시 |
|---|---|
| `META_ACCESS_TOKEN` | System User 장기 토큰 |
| `META_AD_ACCOUNT_ID` | `302364841487753` |
| `META_CAMPAIGN_IDS` | 2기 캠페인 ID (쉼표구분) — **개설 후 입력** |
| `ADMIN_PASSWORD` | `/admin` 비밀번호 |
| `ADMIN_SESSION_SECRET` | 긴 랜덤 문자열 |
| `GITHUB_TOKEN` | 이 저장소 Contents R/W 만 |
| `GITHUB_REPO` | `owner/vibe2-dashboard` |
| `GITHUB_BRANCH` | `main` |
